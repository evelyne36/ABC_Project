# 数据集规模与预处理口径

更新时间：2026-06-24

本文记录 synthetic 与 TabArena 实验中的数据规模口径，便于论文表格、实验设置说明和答辩问答引用。

## 1. Synthetic 数据规模

Synthetic 主实验的特征数由实验维度参数控制，样本数由 protocol 中的 `n_samples` 控制。

当前代码口径：

| 协议 | 样本数 | 特征数 | 说明 |
|---|---:|---:|---|
| `synthetic_main_random300_single_seed` | 3000 | 10 / 20 / 50 | 正式 single-seed Random300 主实验口径 |
| `synthetic_main_framework_smoke` | 180 | 10 | framework smoke，只用于验证流程和输出格式 |

注意：`synthetic_metagb/EXPERIMENT_DESIGN_ZH.md` 中曾写 `10 / 50 / 100`，但当前代码 `synthetic_metagb/protocols.py` 的实际维度是 `DIMENSIONS = [10, 20, 50]`。因此论文和结果解释应以当前代码和结果文件为准，除非后续重新改回并重跑。

生成逻辑：

- `main_experiment_instances(n_samples=3000)` 为正式 synthetic 主实验设置每个 cell 的样本数。
- 每个 scenario 先生成结构所需的有效特征，再由 `generate_instance(..., target_features=dimension)` 补充无关高斯特征到指定总特征数。
- 补充无关特征来自 `Normal(0, 1)`。

主要证据文件：

- `synthetic_metagb/protocols.py`
- `synthetic_metagb/scenarios.py`
- `synthetic_metagb/results/synthetic_main_framework_smoke_dim10_20260615/protocol.json`

## 2. TabArena 预处理口径

TabArena 原始规模直接来自 `dataset/TabArena_*/*.csv`：

- `raw_samples`：CSV 数据行数，不含表头。
- `raw_features`：CSV 总列数减 1，默认最后一列为 target。

预处理后规模按当前 `random600/utils/runner.py` 的 `load_dataset()` / `preprocess_features()` 统计：

- `drop`：先删除 target 缺失行，只保留数值特征，再删除特征缺失行。
- `onehot`：先删除 target 缺失行，再删除任一特征缺失行，然后对非数值特征做 `pd.get_dummies(..., drop_first=False)`。
- 对 regression，target 会再转为 numeric，并删除 target 转换失败的行。
- 对 binary / multiclass，target 使用 `pd.factorize(..., sort=True)` 编码。
- `ValueError` 表示该数据集在对应预处理口径下无法进入实验，例如无行或无可用特征。

## 6. Drop 与 OneHot 等价性审计

按当前 `random600/utils/runner.py` 预处理逻辑检查全部 49 个 TabArena 数据集：

### 6.1 行数等价性

如果只关心最终样本数是否一致，而不要求特征列数一致，则：

| 范围 | 数据集数 | drop/onehot 均可用 | 两者均失败 | 仅一种可用 | 均可用且行数一致 | 均可用但行数不同 |
|---|---:|---:|---:|---:|---:|---:|
| Regression | 11 | 11 | 0 | 0 | 11 | 0 |
| Binary | 30 | 28 | 1 | 1 | 26 | 2 |
| Multiclass | 8 | 5 | 1 | 2 | 5 | 0 |
| **Total** | **49** | **44** | **2** | **3** | **42** | **2** |

真正行数不同的数据集只有 2 个：

| Task | Dataset | Drop samples/features | OneHot samples/features |
|---|---|---:|---:|
| Binary | `HR_Analytics_Job_Change_of_Data_Scientists.csv` | 19158 / 2 | 8955 / 177 |
| Binary | `in_vehicle_coupon_recommendation.csv` | 12684 / 7 | 108 / 59 |

因此，如果论文只讨论 post-preprocessing sample count，可以写：

> Among the 44 TabArena datasets for which both drop and one-hot preprocessing succeeded, only 2 datasets had different post-preprocessing sample counts; the remaining 42 had identical sample counts.

### 6.2 完整矩阵等价性

如果要求最终训练矩阵的行数和特征数都一致，则：

| 范围 | 数据集数 | drop/onehot 均可用 | 两者均失败 | 仅一种可用 | 均可用但行数不同 | 均可用但特征数不同 | 最终训练矩阵不等价 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Regression | 11 | 11 | 0 | 0 | 0 | 5 | 5 |
| Binary | 30 | 28 | 1 | 1 | 2 | 13 | 14 |
| Multiclass | 8 | 5 | 1 | 2 | 0 | 2 | 4 |
| **Total** | **49** | **44** | **2** | **3** | **2** | **20** | **23** |

这里的“最终训练矩阵不等价”包括：

- 仅一种预处理可用；
- 两种预处理均可用，但处理后的行数或特征数不同。

仅一种预处理可用的数据集：

| Task | Dataset | Drop | OneHot |
|---|---|---|---|
| Binary | `Diabetes130US.csv` | ok | failed: no rows remain |
| Multiclass | `splice.csv` | failed: no feature columns remain | ok |
| Multiclass | `website_phishing.csv` | failed: no feature columns remain | ok |

两种预处理都失败的数据集：

| Task | Dataset | 原因 |
|---|---|---|
| Binary | `kddcup09_appetency.csv` | no rows remain after preprocessing |
| Multiclass | `MIC.csv` | no rows remain after preprocessing |

结论：不能把当前实验描述为“先统一删除所有含缺失值的行，然后分别做 drop 或 onehot”。更严谨的表述是：

> For one-hot preprocessing, rows with missing values in any feature are removed before one-hot encoding. For drop preprocessing, non-numeric feature columns are removed first, and missing-value filtering is then applied only to the remaining numeric features.

因此，drop 与 onehot 在 23/49 个 TabArena 数据集上产生不同的最终训练矩阵；论文中应将两者作为不同预处理条件报告。

## 8. MetaGB 计算压力口径

MetaGB 的计算量对预处理后的特征数非常敏感。粗略地说，如果同时枚举 conditional features 与 predictive features，则特征数会近似以平方形式放大计算压力。因此除了分别报告 `processed_samples` 和 `processed_features`，本文也记录一个简单的压力代理指标：

```text
pressure_proxy = processed_samples * processed_features^2
```

这个指标不是精确运行时间模型，但能帮助识别宽表或 one-hot 后特征爆炸的数据集。

## 9. 写作建议

论文中建议分清两个口径：

1. Dataset description table 使用 `raw_samples` 和 `raw_features`，说明数据集原始规模。
2. Experiment protocol / appendix 使用 `drop_samples/drop_features` 与 `onehot_samples/onehot_features`，说明模型实际看到的矩阵规模。

如果某数据集在某预处理口径下失败，不应把原始规模当作实际训练规模；应明确写为 excluded under that preprocessing because no rows/features remain after preprocessing。
