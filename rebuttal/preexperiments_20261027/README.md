# 本地预实验：乐观真实数据预选与效果—成本方向（2026-10-27）

**最新方向已获用户确认：** [下一步研究方向与证据入口](下一步方向_用户确认_20261027.md)。以下按历史预实验轮次保留原结果；后续方向以该确认记录为准。

**建议主攻 kin8nm 与 ILPD；vowel 作精度型扩展。** 这三项都已有历史优于XGB的线索，本轮预留小留出集复核仍正向。当前证据更适合检验“额外单轮搜索是否换来更少迭代，以更低时间达到目标效果”，而不是宣称每棵CrossGB都更便宜。

本次只做本地探索、预选和小规模机制测试。未动正式外层测试折、未改核心算法、未派发远端任务、未提交/推送。原始数据没有外发。

## 1. 真实数据怎么筛的

- 从本地原实验与TabArena目录选52个真实表格数据文件：原tabular面板（排除人工生成的friedman1）、全部本地TabArena回归文件，以及历史有正向线索的TabArena分类文件。
- 成功筛查62个预处理设置，每设置2个development划分、3个配置、4个模型，共1488次小拟合。6个设置/数据因维数上限、类别过少或无数值特征跳过，完整保留原因。不同预处理不是不同独立数据集。
- 方法：原生XGB、CrossGB、LGB constant、LGB linear。分类接入通过小型验证；Lin作者分类接口只输出硬标签，本次没有把它硬凑进AUC表。PL不在这轮本机测试中。
- 先预留seed42的outer1测试折（约20%，始终不评分）；其余80%再分成发现池与小留出复核池。发现时训练/验证均不碰留出池。按发现指标和历史线索冻结两批共13项，再评估小留出。
- 每次发现最多1800行，100 boosting rounds，深度3/4，3个预声明配置；预测候选比例1/.5/.25。缺失处理、标准化和onehot均只在训练内拟合；numeric-only drop另报。删除`predefined.set`和`Unnamed: 0`元信息列，不给模型预定义train/test标签。
- 留出复核训练最多4000行。三次拟合主要复测计时/大数据训练子样本；它们共用一个留出集，**不是3个独立外折**。旧native updater会把内部C RNG初始化为1，不能把不同random_state直接当独立CrossGB随机重复。

全量发现表、13项留出复核表及逐fit记录均在`results/`，没有只保留赢家。历史报告用于有意识地找案例，这里不声称无偏benchmark胜率或已验证的选模器。

## 2. 推荐名单：冻结小配置后的留出结果

| 数据/指标 | CrossGB | XGB | LGB constant | LGB linear | 对XGB改善 | 对LGB linear改善 | 优先级 |
|---|---:|---:|---:|---:|---:|---:|---|
| **kin8nm / RMSE↓** | **0.127345** | 0.157229 | 0.157608 | 0.140171 | **19.0%** | **9.2%** | **P0：效果与成本主攻** |
| **ILPD drop / AUC↑** | **0.762225** | 0.715096 | 0.710489 | 0.685330 | **+4.71个百分点** | **+7.69个百分点** | **P0：小样本二分类主攻** |
| **vowel / logloss↓** | **0.311239** | 0.438848 | 0.377237 | 0.361707 | **29.1%** | **14.0%** | **P1：精度扩展，效率与更强常数基线待确认** |

这些都是本轮特定小配置/单一留出下的预实验值，不能代替原论文完整协议。kin训练4000、留出1639；ILPD训练349、留出117；vowel训练594、留出198。ILPD和vowel留出很小，需要正式重复划分确认，不做显著性声明。

与历史的关系：旧报告中kin对XGB约10.9% RMSE改善；ILPD约+1.78–2.00 AUC个百分点；vowel约42–44% logloss改善。新预实验没有“创造”这些线索，而是在另一套受限协议下检验它们是否值得排正式任务。

**更强近邻仍是硬约束。** 既有完整N1中PL在kin优于CrossGB；本轮胜过XGB/LGB不能升级成“胜过全部线性叶方法”。下一步必须在这三个候选上对齐实际近邻与搜索协议。

### 降级与保留的反例

- **diamonds drop**：发现阶段同时胜XGB/LGB linear，小留出反而比XGB差14.4%、比LGB linear差6.6%。不推荐作主正例。
- **Moneyball**：历史略胜XGB，本轮小留出比XGB差10.2%；n=114、onehot后维度较高，暂不优先。
- **phoneme**：小留出对XGB约+0.44 AUC个百分点，但仍比LGB linear低约0.22个百分点。适合XGB选择性收益，不能说明近邻领先。
- **airfoil**：小留出对XGB好11.9%，但对LGB linear只好0.45%，且历史完整结果方向相反。仅候补。
- **mfeat-fourier**：logloss比XGB好5.1%、比LGB linear好10.0%，但本轮终拟合约21.6秒，对照约0.22–0.28秒；不适合本轮主打资源优势。
- **jm1/mozilla/vehicle**：部分发现结果在小留出中未保持对XGB的收益。完整数值在表中，不将发现胜率当确认结果。

## 3. 计算时间应该怎样论证

同样100轮时，CrossGB通常更慢。例如小留出复核，kin约111ms vs XGB16ms，ILPD约17ms vs XGB6ms，vowel约310ms vs XGB68ms。不能用相同轮数直接宣称速度优势。

我进一步在发现池中做了固定配置的10/30/100/300/900轮曲线，并对ILPD/vowel给所有四个模型同样的有限learning-rate扩展（.05/.2/.5×20/60/180轮）。这些曲线仍只评估发现池，**不是留出复核上的新确认结论**。

下列为同一数据、训练样本和验证样本下的本机暖启动观测：

| 训练内工作点 | 效果 | 终拟合wall | 可检验信号 |
|---|---:|---:|---|
| kin：CrossGB 100轮 | RMSE 0.140616 | 39.2ms | 对下列XGB误差更低，约2.2倍快 |
| kin：XGB 900轮 | RMSE 0.1532 | 87.0ms | 参考工作点 |
| kin：LGB linear 300轮 | RMSE 0.1549 | 40.1ms | 与CrossGB近似同时间，CrossGB误差低约9.2% |
| ILPD：CrossGB 20轮，lr=.05 | AUC 0.752381 | 3.69ms | 对下列XGB/LGB linear均是更高AUC、更少时间 |
| ILPD：XGB 180轮，lr=.05 | AUC 0.718095 | 8.20ms | 本轮LR曲线中XGB的最佳AUC点 |
| ILPD：LGB linear 180轮，lr=.05 | AUC 0.734603 | 11.01ms | 本轮LR曲线中linear的最佳AUC点 |
| ILPD：LGB constant 20轮，lr=.05 | AUC 0.745714 | 1.32ms | 更便宜、AUC略低；CrossGB并未支配所有方法 |

这是**观测到的候选工作点**，不是同总搜索预算下的优胜证明。配置发现本身也消耗时间，CrossGB的发现成本更高；毫秒级计时还需目标Linux机、明确CPU/线程/负载与重复计时确认。计时只含fit，排除了导入、预处理、超参搜索；CPU秒原值也已保存，不能叫FLOPs或完整流水线加速。

vowel的价值目前更偏精度。扩大learning-rate后，发现池上的LGB constant可达到logloss0.2601，而CrossGB最佳约0.2754，说明强基线调参仍可能改变排序。正式实验应给对手合理学习率范围，不能只拿lr=.1的弱工作点比较。

**建议正式报告两张表：**
1. 同总搜索预算（如60/300/900秒）下选出的held-out效果，终拟合另记。
2. 冻结配置的time-to-quality曲线，以及CPU/预测耗时、树/叶规模。只比较已观测点，不外推对手“永远达不到”。

## 4. 新synthetic：已有正向预实验，但优势有边界

生成器在`../analysis_20261027/synthetic_mechanism_suite.py`。本次实际跑7种设置，所有方法拿相同完整X，不给CrossGB真实gate/active-support标签。

核心设置是**零条件均值的局部斜率/角色切换**：gate划分区域，区域内只用一个预测变量，相邻区域反号，预测变量按区域组切换。c和z独立中心化，使标准单变量均值分裂缺乏明显的总体根部信号；预测感知的局部响应评分有可利用信号。这扩展了已有regime_slope/feature_switch，不把旧机制改名当新贡献。

发现网格：样本600/2400、维度8/32、区域2/4，以及dense/offset/step对照；噪声σ=.3。3个发现seed选配置后，**先冻结每方法配置，再换3个全新数据seed53001–53003**。廉价XGB/LGB额外扩展到1024轮，避免只用64轮欠拟合对照。Lin使用固定作者实现，只测两个d8稀疏设置；无PL结果。

新数据seed下的RMSE均值：

| 设置 | CrossGB | XGB | LGB linear | LinXGB | CrossGB / LGB linear拟合时间 |
|---|---:|---:|---:|---:|---:|
| 稀疏，n600/d8/2区域 | **0.4119** | 0.7727 | 0.6738 | 0.3272 | 14.6 / 73.6ms |
| 稀疏，n600/d8/4区域 | **0.6928** | 1.1710 | 1.0483 | 0.6636 | 14.7 / 72.2ms |
| 稀疏，n600/d32/4区域 | **0.6177** | 1.9142 | 1.8030 | 未测 | 3.75 / 117.7ms |
| 稀疏，n2400/d32/4区域 | **0.4505** | 1.2974 | 1.0839 | 未测 | 296.6 / 177.5ms |
| 稠密4变量，n600/d32/4区域 | **1.0865** | 2.0499 | 2.0490 | 未测 | 141.0 / 1.31ms |
| 区域截距，n600/d32/4区域 | 0.6971 | 0.9328 | **0.6596** | 未测 | 140.0 / 8.25ms |
| 纯阶跃，n600/d32/4区域 | 0.6583 | 0.6900 | **0.4601** | 未测 | 3.55 / 1.15ms |

各方法用自己的冻结配置，轮数可能不同；表内粗体仅提示CrossGB对原生XGB/LGB linear的相对位置，不含Lin排名或显著性。完整均值、SD、轮数、学习率、CPU/wall时间均在CSV中，均值只来自3个独立生成数据seed。

**最值得继续的机制：** n600/d32/4区域的稀疏切换，CrossGB相对本轮冻结LGB linear约低65.7% RMSE，终拟合约31倍快；其CrossGB配置只需1轮，LGB linear为1024轮。这是窄机制下的实现结果，不是一般表格结论。

**对真正灵活近邻的边界：** d8/4区域中Lin更准（0.6636 vs0.6928），CrossGB终拟合约14.7ms vs1.646s。这里支持的是当前原生实现相对该Python矩阵求解实现的成本取舍，不能推广到原生PL或其他优化线性树。d8/2区域Lin的精度优势更明显。

负对照必须保留：区域截距下LGB linear同时更准、更快；纯阶跃也由普通/线性LGB占优。稠密情形中CrossGB虽然胜本轮原生对照，但绝对误差高，且未跑全变量Lin，不能据此主张k=1最优。原先预声明的“所有3个发现seed均达RMSE≤.45”目标没有模型/设置稳定达成，不放宽目标宣称成功。

## 5. 推荐的后续方向与停止条件

1. **真实主攻：kin8nm + ILPD。** 把“效果收益能否在合理搜索预算内兑现”作为问题；vowel补充精度，不预设其效率领先。下一次正式队列应对齐PL/Lin/LGB的实际支持范围、学习率/正则空间、数据预处理和外层划分。
2. **synthetic主攻：零均值gate×局部斜率、区域预测变量切换。** 在R、n、d、噪声、稀疏度上做预声明轴变化；在同一网格配对保留dense/offset/step。逐步检验“单轮联合搜索代价→更少迭代→time-to-quality”的链条。
3. **补强近邻，不另造弱基线。** 本机结果只覆盖XGB/LGB与部分Lin；正式主张仍须原生PL。PILOT/TAO保留正确模型族标签，不拿单树差距代替boosted近邻比较。
4. **评价优先顺序：同搜索时间的held-out效果、达到预声明误差的时间、终拟合与预测、模型规模。** 精度只提高一点却慢几十倍的mfeat类任务不优先。
5. **不要继续扩大真实数据筛选以凑胜例。** 这一轮主候选已足够具体；正式新结果若不保持，记录边界、降级主张。本轮52文件/62设置和13项复核记录全部保留。
6. **当前停止在预实验。** 不改变方法为新的k>1/affine版本，不使用保留outer-test调参，不远端派发大队列。正式实验由后续同步的工程和研究员执行。
