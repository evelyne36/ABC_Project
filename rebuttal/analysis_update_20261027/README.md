## 1. N3：成本换收益只在 kin8nm 上初步兑现

数字为五个外折 test RMSE 的均值，低者更好。计时口径是相同**搜索时间上限**，终模型 refit 另计。

| 数据 | 搜索上限 | CrossGB | XGB | CGB/XGB 平均完成候选数 |
|---|---:|---:|---:|---:|
| kin8nm | 60s | 0/5 折有完成候选 | 0.120132 | 0 / 8 |
| kin8nm | 300s | 0.110984 | 0.114745 | 9 / 33.6 |
| kin8nm | 900s | 0.107158 | 0.110540 | 25 / 105.8 |

| energy_efficiency | 300s | 0.361349 | 0.357941 | 21 / 160.2 |

| cpu_activity | 900s | 130.520636 | 2.204368 | 9 / 61.8 |

kin8nm 在 300/900s 的误差改善约为 3.28%/3.06%，但最终 refit 均值分别为 CGB 4.22/15.86s、XGB 2.55/4.52s；不是全流程严格等时。Energy 未出现效果优势。CPU 的有限且极大的误差是**既定候选顺序与搜索上限下的真实失败结果**，除非后续证实输入、实现或记录错误，否则必须保留，不能因它不代表充分搜索上限而删去。

现有 T3 将 CPU 900s 删去的建议不适合采纳。相同预算本来就在衡量“能否在有限时间完成足够搜索”。同时，这只覆盖一个预先固定的候选顺序；第一个 CGB CPU 候选耗时约 350s，使 60/300s 都没有完整候选，候选顺序敏感性尚未验证。另，“完成候选数之比”不能直接叫“单候选耗时比”，因完成的配置集合不同。

## 2. LightGBM：近邻压力继续成立，但汇总不能删折排名

| 数据 | CrossGB 既有 N1 | LGB linear 五折均值 | LGB constant 五折均值 |
|---|---:|---:|---:|
| cpu_activity | 3.934443 | 176.537120 | 2.235670 |
| kin8nm | 0.100273 | 0.100387 | 0.105404 |
| curved_control | 0.162995 | 0.156076 | 0.160540 |
| feature_switch | 0.215787 | 0.158570 | 0.168412 |
| regime_slope | 0.237478 | 0.224102 | 0.335993 |

kin8nm 的 CGB/LGB linear 差约 0.11%，当前不宜据此宣称实质领先。其余三个稳定任务上，LGB linear 更准。CPU 中 LGB linear 的 outer4 为 873.941397，必须计入五折均值；可同时报告中位数和逐折值，但不能把删折后的 2.1861 与其他方法五折均值排名，也不能写“线性叶五数据全胜”。PL 的异常折同样保留。

该异常折的内层均值为 **2.212852**，并非内层已经出现相同量级的爆炸。因此当前更值得检查 selected refit/测试分布上的极端预测、系数、叶支持和缩放。尚无证据认定具体根因，更不能直接断言“已知数值问题，协议无误”。

还有两处应纠正的描述：

- 按 LightGBM [官方参数文档](https://lightgbm.readthedocs.io/en/stable/Parameters.html#linear_tree)，线性叶使用该叶路径上的数值特征，首棵树为常数叶；不是任意全输入特征上的仿射叶。LinXGBoost 与 LGB linear 的机制不可合并。
- 本批 50 个摘要均为 `standardize=false`；官方文档建议特征尺度相近。因此可做训练内缩放的补充敏感性分析，旧结果照报。缩放可能影响截距受限的 CGB 及正则含义，需要对各方法明确记录，不能混成原协议。

N1 实际是两个真实/仿真来源基准与三个合成任务，不是“五个真实数据集”；Lin 20 候选、其他方法不同池及超时口径也不能概括成同一 300 候选协议。

## 3. N2：支持条件性机制，四格必须使用真正的 Bias

`Bias` 与原生 `XGB` 不数值等价：单个 seed 的 pooled 指标最大差约 0.11859。R0 核对的是新旧实现重放，不等于证明 Bias=XGB。

以下是**先在 seed 内拼接五折损失、再对三个 seed 取均值**的结果，与旧表的平均 fold RMSE 口径不同：

| 机制 | Bias | LeafOnly | SplitOnly | Full | 原生 XGB |
|---|---:|---:|---:|---:|---:|
| regime_slope / RMSE | 0.538008 | 0.592910 | 0.322381 | 0.302022 | 0.544253 |
| feature_switch / RMSE | 0.225684 | 0.218936 | 0.231275 | 0.204906 | 0.218780 |
| categorical_regime_slope / RMSE | 0.325801 | 0.413264 | 0.380339 | 0.323129 | 0.377772 |
| curved_control / RMSE | 0.159072 | 0.156769 | 0.169186 | 0.161194 | 0.159440 |
| pure_step_control / RMSE | 0.242220 | 0.246623 | 0.250145 | 0.251021 | 0.257780 |
| regime_logit / logloss | 0.401724 | 0.407009 | 0.381106 | 0.421879 | 0.402655 |
| sparse_multiplicative / RMSE | 0.665145 | 0.838295 | 1.152856 | 1.866967 | 0.640433 |

Full 相对 LeafOnly 在前三项改善，在后四项退化。Full 相对 SplitOnly 的差才是 predictive-scored 路由下更换叶模型的条件性增量；Full 相对 LeafOnly 的差是 predictive leaf 下更换评分的增量。不能把 LeafOnly−SplitOnly 当单因素贡献。真正 2×2 底角为 Bias；原生 XGB 另列实现参照。

N4 的路径外变量统计已经核实，但“CPU 使用更多路径外变量，所以它失败”仍是待检验假设。两数据集同时在训练轮数、树规模、特征分布等方面不同。kin 的叶总数比 XGB 更多，当前也不支持整体模型更小。

## 4. 下一轮的主问题及顺序

### P0：先确认局部稀疏机制和 Linux 近邻，不继续找更多赢面数据

保留已冻结五新 seed 结果：CGB 0.357617、补强 Lin 0.368492，4/5 次较好；配对差均值 −0.010875，SD 0.023660。这个幅度不足以视为稳定精度优势。本机约 3ms/704ms 的差异含实现和硬件因素。

先在 Linux 对 sparse、dense、offset、step 四个设置各做 10 个新独立数据 seed，六方法 CGB/XGB/LGB constant/LGB linear/PL/Lin，共 **240 个确认终拟合**。使用新开发数据合理增强近邻，再冻结配置，最后一次性评估全新 test 数据。保留早期冻结配置复现作为单独校准，不能与增强后比较混合。

需要记录：RMSE、搜索 wall/CPU、终拟合 wall/CPU、预测耗时、树/叶/系数数，以及失败和超时。计时比较必须同机、同核、单线程；六种方法在同一数据任务内顺序运行，预先平衡先后次序。毫秒级 fit 单独暖机并重复计时，重复计时不算独立统计样本。跨 CPU 架构的原始时间不直接混合排名。

### P1：确认后作单轴扫描，检验优势在哪消失

基准 n=240、d=32、活跃斜率 k=1、区域截距 a=0、两区域、噪声 SD=0.3。

| 改变因素 | 水平 | 要回答的问题 |
|---|---|---|
| 样本量 n | 120 / 240 / 480 / 960 | 样本增多后，灵活叶是否追平或反超？ |
| 总维数 d | 8 / 32 / 64 | 无关变量是否扩大估计/搜索成本差异？ |
| 活跃斜率 k | 1 / 2 / 4 | k=1 的收益是否随真实稀疏性消失？ |
| 区域截距 a | 0 / 0.5 / 1 | 无截距叶的限制何时显现？ |
| 纯阶跃 | 同 X、同噪声 | 均值分裂足够时，预测评分是否多余？ |

以单轴为主，去重后 **11 个设置 × 10 seeds × 6 方法 = 660 个终拟合**，包含首批 240 个，不再加一遍。不是 4×3×3×3 全组合。开发/HPO、暖机和计时重复另计。

建议开发 seeds 95001–95003、确认 seeds 96001–96010，在执行前核对全项目未用过并冻结；确认每份数据用 60/20/20 train/validation/test。开发集用于跨三个独立生成数据集选参；新确认数据上的 validation 保留，主要终测使用冻结配置在 train 上拟合，防止确认阶段继续选参。随后若做 train+validation refit，需作为另一个预先声明口径。

跨 k/a/step 共用 X、噪声和划分；跨 d 使用同一高维母样本的嵌套列、跨 n 使用嵌套训练/验证/测试行。现有生成器按 d/n 改变随机数消耗，不能直接声称这些轴已经配对。信号使用 `2*s(c)*(sum(z_active)/sqrt(k)+a)/sqrt(1+a²)`，使总体信号方差维持为 4；step 使用 `2*s(c)`。新生成器与旧结果分版本记录。不给任何正式方法真 gate/support 标签。

合理搜索范围必须含浅 Lin、强弱正则、PL 的 half_additive/linear 和不同叶支持，以及 XGB/LGB 的充分 boosting 轮数。不同库的 depth 定义分别记录。建议每方法每设置最多 300s 的开发搜索，完整评估三个开发 seed 的候选才可选；**66 个方法×设置搜索单元，上限约 5.5 单核小时**，选定后的终拟合另计。60s 前缀可同时保存。该预算是新协议提案，不是既有正式运行结果；实际运行前须补齐并冻结候选池及执行清单。

### 与主线并行的定向补洞

1. **CPU 数值失败诊断**：先看 CGB N3 的有限前缀和 LGB/PL 的异常外折，核对候选、输入/预处理哈希、预测范围与模型系数；单独重放已选配置。若做训练内缩放/正则敏感性补充，保留原负结果，不能看 test 后替换主表配置。没定位前不宣布算法或实现根因。
2. **时序对齐**：使用找回的 frozen manifest 核对目标时间、h−1 gap、scaler fit 范围和数据哈希。优先重放 Exchange h1、ILI h1、ETTh2 h1 的 selected CGB；对齐后再决定是否需要多起点。当前快照中 CGB 对最强简单参照为 0/10，但仍须注明旧 CGB 与新参考的可比性边界。
3. **真实证据**：先 kin8nm 强近邻同预算；ILPD 作为观测二分类候选，vowel 次之。已有 PL/Lin 适配器仅支持标量回归，不能直接加入概率指标表；未实现正确分类支持就标为不支持。kin 本身为仿真来源，不能冒称真实观测机制验证。停止继续无目的扩充数据。
4. **N5 降为有门槛的 P1**：现有五台工程的结果目录未发现 N5 结果，也未检测到 N5 任务。当前本地执行器每轮梯度沿原模型 cursor 更新，各 k 变体没有自己的残差；并根据 test 是否落入某叶决定是否 refit。它不能直接称为已规划的 stagewise k>1 refit。正式执行前，应明确每个变体沿自身训练预测更新残差、训练内决定全部叶参数，核验 k1 stored 重放及 raw/bin 控制；否则仅可另标成沿原模型梯度的系数敏感性探针。此次未改该执行器或启动容量任务。
