### `tabular_extra_random300`

目的：扩展 TabPFN 之外的 tabular 数据，优先选择 MetaGB 匹配度较高、计算经济性好的数据。

实验架构：

- nested CV 外 5 内 4。
- Random300 候选。
- 默认 `categorical-handling=ordinal`，也可切换 `drop` / `onehot` 做处理方式对照。
- 数据选择以 `samples * features * features` 压力代理排序，尤其控制 feature 数，因为 MetaGB 成本对 feature 近似平方增长。

清单：

- 全量候选：`tabular_extra_random300/candidate_inventory.csv`

### `timeseries_extra_random300`

目的：补充能体现 MetaGB 优势的 time-series 数据，同时新建工程，避免影响旧 time-series adapter。

实验架构说明：

- 数据来源优先采用顶会 LTSF / multivariate forecasting 常见数据，如 ETT family 与 LSTNet exchange_rate。
- 对 XGBoost/MetaGB，采用监督式滑窗把 time-series 转为 tabular 样本。
- 保持时间有序切分，不 shuffle。
- 外层和内层均为 expanding-window chronological split。
- scaler 只在训练窗口 fit，避免未来信息泄漏。
- time-series 一般无离散特征，因此不做 onehot；只考虑数值窗口特征。

已落盘数据：

- `ETTh1.csv`
- `ETTh2.csv`
- `ETTm1.csv`
- `ETTm2.csv`
- `exchange_rate.txt`

清单：

- 全量候选：`timeseries_extra_random300/candidate_inventory.csv`
- 已筛选队列：`timeseries_extra_random300/selected_manifest.csv`
- 原始数据：`timeseries_extra_random300/data/raw/`

smoke 结果：

- `smoke_timeseries_extra_etth1_20260627`
- `summary_rows=2`
- `candidate_rows=60`
- 覆盖 `xgb_cpu` 与 `current_metagb` 各 30 候选。

## 推荐执行顺序

1. 先跑 `tabarena_30` 中 queue pressure 最低的数据。
2. 再跑 `tabular_extra_random300` 第一批低压力数据。
3. 再跑 `timeseries_extra_random300` 的 `exchange_rate -> ETTh1 -> ETTh2`。
4. `ETTm1/ETTm2`、大 TabArena 数据、宽通道 time-series 数据放到后续服务器窗口。
5. 所有 full run 建议 `--task-workers 15 --n-jobs 1`，避免 XGBoost 内外层并行过度抢核。
