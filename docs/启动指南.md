## 三个实现的关系

原版 `metagb/` 是 standalone MetaGB：`metagb_utils.MetaGB` 通过 CFFI 调 `libmetagb`，v3 简化版把特征分成 conditional feature 和 predictive feature，叶子预测为 `beta * x_j`，并追加 bias feature 以退化到普通 GB。

`current_metagb` 是嵌入到 `beforereview/xgboost-master` 的版本：当 Python 参数传入 `enable_metagb=True`，`GBTree::Configure` 会把 updater 切到 `grow_metagb_histmaker`，只支持 CPU `hist`。核心代码在：

```text
beforereview/xgboost-master/src/tree/updater_metagb_hist.cc
beforereview/xgboost-master/src/tree/param.h
beforereview/xgboost-master/src/predictor/cpu_predictor.cc
beforereview/xgboost-master/src/tree/tree_model.cc
beforereview/xgboost-master/python-package/xgboost/sklearn.py
```

官方 XGBoost 路径仍保留：不传 `enable_metagb=True` 时使用标准 CPU hist updater。`current_metagb` 额外把 MetaGB leaf feature 写入树模型，预测时遇到 MetaGB 树会用 `leaf_value * selected_feature_value`，bias feature 则等价于普通叶子常数。

多分类任务的默认路径是 **k-class scalar tree**，也就是 XGBoost 的 `multi_strategy=one_output_per_tree`：每个 boosting round 为 `K` 个类别分别训练一棵 scalar MetaGB tree。当前服务器主实验不需要、也不应该额外设置 `multi_strategy`；只要不显式传入 `multi_strategy="multi_output_tree"`，就会保持这个默认路径。`multi_output_tree` 是保留的 experimental vector 分支，用于消融/压缩结构实验，不作为当前主结果默认配置。

当前保留的训练加速路径是 C++ CPU hist updater 内部的自动 histogram build 策略：

```text
METAGB_HIST_BUILD_MODE=auto|row_serial|cf_parallel|row_parallel
```

默认 `auto` 会在较宽、单节点工作量较大的场景选择 `cf_parallel`，在小表上保留轻量路径。直方图减法经过复测没有稳定加速收益，反而会因为保存/复制完整 3D node histogram 带来额外开销，因此 `metagb_hist_subtract` 当前默认是 `false`。只有做消融时才显式打开 `--metagb-hist-subtract`。

## Linux 服务器编译

macOS 编译出的 `.dylib` 不能在 Linux 使用。迁移到 Linux 后必须在目标服务器重新编译 `xgboost-master`，生成 Linux 的 `.so`。

推荐依赖。当前 `xgboost-master/python-package/xgboost/core.py` 需要 Python 3.10+，服务器上不要用 Python 3.9 或更低版本：

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install -y build-essential cmake ninja-build python3 python3-pip

# 或 conda
conda install -c conda-forge cmake ninja compilers -y

python3 --version
python3 -m pip install --upgrade pip setuptools wheel
python3 -m pip install numpy pandas scipy scikit-learn
```

编译当前嵌入版：

```bash
cd ./beforereview/xgboost-master
rm -rf build
mkdir build
cd build
cmake .. -DUSE_OPENMP=ON -GNinja
cmake --build . -j"$(nproc)"
```

验证 Linux 产物：

```bash
ls -lh ./beforereview/xgboost-master/lib/libxgboost*.so*
```

如果曾在 macOS 或另一台机器生成过 `build/`，一定先 `rm -rf build`。CMake cache 绑定了编译器、Python ABI、OpenMP runtime 和平台库后缀，不能跨机器复用。

## 编译后验证

从项目根目录进入 `./beforereview` 后运行：

cd ./beforereview

## Random500 论文主实验

`random500/` 是当前建议优先使用的论文主实验工程。当前主实验用于在 regression、binary、multiclass 三类数据上按 exp1 random search 方式比较：

```text
xgb_cpu
current_metagb
```

`current_metagb_pred0` 是后续副实验/ablation，用于检查 `pred_feature_fraction=0` 的退化诊断组，不放进当前主实验默认启动命令。

默认路径均从项目根目录推导，不依赖本机绝对路径：

```text
./dataset/TabArena_regression
./dataset/TabArena_binary
./dataset/TabArena_multiclass
./beforereview/xgboost-master/python-package
./random500
```

`configs_xgboost.json` 的默认位置是早期 exp12 配置文件：

```text
./beforereview/exp12/configs_xgboost.json
```

若该文件存在，`xgb_cpu` 会优先读取其中最多 200 组配置，再按 `random500/configs/default_search_space.json` 补齐到 500 组。若该文件不存在，脚本会直接生成完整 500 组，并在 `run_metadata.json` 和 `parameter_audit.json` 中记录 warning。也可以用 `--xgb-config /path/to/configs_xgboost.json` 指定其他位置。

Random500 的 `current_metagb` 多分类默认使用 **k-class scalar tree**。脚本不会显式传入 `multi_strategy`，因此会沿用 C++ 默认的 `one_output_per_tree`。除非专门做 vector 分支消融，否则不要在服务器主实验里添加 `multi_strategy="multi_output_tree"`。

## Random500 快速冒烟

从项目根目录执行。这个命令只验证环境、路径、分类/回归流程是否可跑，不代表正式结果：

```bash
python3 random500/scripts/run_random500_server.py \
  --mode quick \
  --task-types regression binary multiclass \
  --regression-datasets airfoil_self_noise.csv \
  --binary-datasets diabetes.csv \
  --multiclass-datasets anneal.csv \
  --models xgb_cpu current_metagb \
  --max-candidates 10 \
  --outer-folds 2 --inner-folds 2 \
  --single-outer-fold --outer-fold-index 0 \
  --task-workers 1 --n-jobs 1 \
  --run-id smoke_random500
```

说明：`current_metagb` 的候选需要均衡覆盖 `pred_feature_fraction=0.1..1.0`，所以包含 `current_metagb` 时 `--max-candidates` 必须能被 10 整除。

## Random200 轻量主实验

`random200/` 是在 `random500/` 基础上拆出的轻量版本，用于快速得到更低成本的主实验对照。它适合服务器环境试跑、低成本筛查、参数效果预判和主实验前的流程确认；最终论文主结果仍可继续使用 `random500` 的 500 candidates 口径。它保留相同的数据集划分、nested CV 流程、日志格式和输出结构，但候选规模降为 200：

```text
xgb_cpu: 从 ./beforereview/exp12/configs_xgboost.json 读取 200 组配置
current_metagb: pred_feature_fraction = 0.1..1.0，每档随机 20 组，共 200 组
```

正式跑 `random200` 前应确认 `./beforereview/exp12/configs_xgboost.json` 存在。脚本仍保留缺失时自动生成候选的 fallback，但论文主实验口径建议使用该配置文件中的 200 组 XGBoost 参数。

快速冒烟：

```bash
python3 random200/scripts/run_random200_server.py \
  --mode quick \
  --task-types regression binary multiclass \
  --regression-datasets airfoil_self_noise.csv \
  --binary-datasets diabetes.csv \
  --multiclass-datasets anneal.csv \
  --models xgb_cpu current_metagb \
  --max-candidates 10 \
  --outer-folds 2 --inner-folds 2 \
  --single-outer-fold --outer-fold-index 0 \
  --task-workers 1 --n-jobs 1 \
  --run-id smoke_random200
```

16 核全量：

```bash
python3 random200/scripts/run_random200_full.py
```

等价展开为：

```bash
python3 random200/scripts/run_random200_server.py \
  --mode full \
  --task-types regression binary multiclass \
  --models xgb_cpu current_metagb \
  --max-candidates 200 \
  --outer-folds 5 --inner-folds 4 \
  --task-workers 16 --n-jobs 1 \
  --experiment-name random200_main_xgb_vs_current_metagb
```

`random200` 和 `random500` 的 current_metagb 默认都关闭 hist subtraction；需要消融时再额外加 `--metagb-hist-subtract`。

## Random500 16 核全量

你的 16 核 CPU 服务器推荐使用任务级并行：`--task-workers 16`，`--n-jobs 1`。这样每个模型内部不再额外开多线程，避免多进程和模型线程互相抢核。

如果主实验只比较 `xgb_cpu` 和 `current_metagb`，仍然优先使用 `--task-workers 16 --n-jobs 1`。原因是 nested CV 实验天然包含大量独立任务：

```text
task_type x dataset x outer_fold x model
```

任务级并行的协调成本最低，也更方便保持每个模型训练的线程口径一致。`--task-workers 4 --n-jobs 4` 只建议用于宽表专项计时或单任务延迟更重要的场景；`--task-workers 1 --n-jobs 16` 不建议作为完整 nested-CV 主实验默认配置，除非当前只剩极少任务无法填满机器。

```bash
python3 random500/scripts/run_random500_full.py
```

上面的简化入口等价于：

```bash
python3 random500/scripts/run_random500_server.py \
  --mode full \
  --task-types regression binary multiclass \
  --models xgb_cpu current_metagb \
  --max-candidates 500 \
  --outer-folds 5 --inner-folds 4 \
  --task-workers 16 --n-jobs 1 \
  --experiment-name random500_main_xgb_vs_current_metagb
```

正式主实验默认逻辑是：

```text
task = task_type x dataset x outer_fold x model
outer folds = 5
inner folds = 4
candidate count = 500
parallelism = task-level workers
```

如果某台机器只跑一种任务类型，例如只跑多分类：

```bash
python3 random500/scripts/run_random500_server.py \
  --task-types multiclass \
  --models xgb_cpu current_metagb \
  --max-candidates 500 \
  --outer-folds 5 --inner-folds 4 \
  --task-workers 16 --n-jobs 1 \
  --experiment-name random500_main_xgb_vs_current_metagb
```

如果不同机器分摊同一任务类型的不同数据集，可以显式指定数据集：

```bash
python3 random500/scripts/run_random500_server.py \
  --task-types binary \
  --binary-datasets diabetes.csv credit-g.csv heloc.csv \
  --models xgb_cpu current_metagb \
  --max-candidates 500 \
  --outer-folds 5 --inner-folds 4 \
  --task-workers 16 --n-jobs 1 \
  --experiment-name random500_main_binary_part1
```

也可以从默认 `all` 中跳过指定数据集：

```bash
python3 random500/scripts/run_random500_server.py \
  --task-types binary \
  --binary-datasets all \
  --skip-binary-datasets APSFailure.csv Diabetes130US.csv \
  --models xgb_cpu current_metagb \
  --max-candidates 500 \
  --outer-folds 5 --inner-folds 4 \
  --task-workers 16 --n-jobs 1 \
  --experiment-name random500_main_binary_without_large
```

跨任务类型统一跳过某些文件名时使用：

```bash
--skip-datasets dataset_a.csv dataset_b.csv
```

## Random500 接口清单

常用任务划分接口：

```text
--task-types regression binary multiclass
--regression-datasets all 或若干 csv 文件名
--binary-datasets all 或若干 csv 文件名
--multiclass-datasets all 或若干 csv 文件名
--skip-datasets 若干 csv 文件名
--skip-regression-datasets 若干 csv 文件名
--skip-binary-datasets 若干 csv 文件名
--skip-multiclass-datasets 若干 csv 文件名
```

常用运行规模接口：

```text
--mode quick/full
--max-candidates 500
--outer-folds 5
--inner-folds 4
--single-outer-fold --outer-fold-index 0   只跑单个外层 fold，用于冒烟
```

常用并行和服务器接口：

```text
--task-workers 16   任务级并行进程数，16 核服务器建议 16
--n-jobs 1          单个 XGBoost/current_metagb 模型内部线程数，主实验建议 1
--progress-every 50
--run-id random500_xxx
--output-root ./random500
```

速度解释口径：

```text
公平比较 original_metagb vs current_metagb: 使用 n_jobs=1
论文主实验 xgb_cpu vs current_metagb: 推荐 task-workers=16, n_jobs=1
宽表专项吞吐/延迟测试: 可额外试 task-workers=4, n_jobs=4
```

注意：原版 standalone `metagb/` 不使用 XGBoost 的 `n_jobs`。因此当 `current_metagb` 使用 `n_jobs=4/16` 时，测到的是嵌入版 XGBoost/OpenMP 内部并行收益，不能直接当作与原版 MetaGB 的公平单核速度比。

常用路径接口：

```text
--regression-dir ./dataset/TabArena_regression
--binary-dir ./dataset/TabArena_binary
--multiclass-dir ./dataset/TabArena_multiclass
--xgboost-python-package ./beforereview/xgboost-master/python-package
--xgb-config ./beforereview/exp12/configs_xgboost.json
--search-space-json ./random500/configs/default_search_space.json
```

常用模型/目标函数接口：

```text
--models xgb_cpu current_metagb              主实验
--models xgb_cpu current_metagb_pred0        后续 pred0 ablation
--binary-objective binary:logistic
--multiclass-objective multi:softprob
--metagb-lambda-l2 1.0
--metagb-score-agg 0
--metagb-pred-value-type raw
--metagb-hist-subtract        仅用于直方图减法消融；默认关闭
--no-metagb-hist-subtract     显式保持默认关闭
```

`metagb_hist_subtract=false` 是当前主结果默认口径。它不是模型语义变化，而是工程性能选择：当前实现保存/复制完整 3D node histogram 的成本高于 sibling subtraction 节省的构建成本。只有做 hist subtraction 消融时才显式打开 `--metagb-hist-subtract`。

查看最终委托给底层脚本的命令但不运行：

```bash
python3 random500/scripts/run_random500_server.py --task-types regression --dry-run
```

若需要自定义随机搜索范围，编辑或复制：

```text
random500/configs/default_search_space.json
```

然后通过：

```bash
--search-space-json random500/configs/your_search_space.json
```

指定。

## Random500 输出

结果默认写入：

```text
random500/results/<run_id>/candidate_configs.json
random500/results/<run_id>/candidates.csv
random500/results/<run_id>/summary.csv
random500/results/<run_id>/aggregate.csv
random500/results/<run_id>/pred_fraction_analysis.csv
random500/results/<run_id>/parameter_audit.json
random500/results/<run_id>/run_metadata.json
random500/logs/<run_id>/
```

三类任务的主指标分别是：

```text
regression: rmse, lower is better
binary: auc, higher is better
multiclass: logloss, lower is better
```

`run_metadata.json` 会记录本次实际选择和跳过的数据集。`parameter_audit.json` 会记录显式设置参数与仍使用默认值的参数，尤其会提醒 `gamma`、`reg_alpha`、`max_delta_step`、`colsample_bylevel`、`colsample_bynode`、`grow_policy`、`max_leaves`、`scale_pos_weight`、`base_score` 等当前未纳入搜索的项。

`random200` 的输出结构完全相同，只是根目录换成：

```text
random200/results/<run_id>/
random200/logs/<run_id>/
```

## 常见问题

`import xgboost` 加载到 pip 版本：在 `./beforereview` 内设置 `PYTHONPATH=xgboost-master/python-package`；如果留在项目根目录，则设置 `PYTHONPATH=./beforereview/xgboost-master/python-package`。也可以运行 `scripts/check_metagb_runtime.py` 检查。

Linux 上还在找 `.dylib`：说明没有在 Linux 重新编译，或复用了 macOS build cache。删除 `xgboost-master/build` 后重新 cmake。

线程过量导致变慢：完整实验建议 `--task-workers` 等于服务器物理/可用核心数，`--n-jobs 1`，让并行发生在任务层而不是每个模型内部再开多线程。

## 附录：Exp12/Exp2 历史流程

`beforereview/exp12` 是早期实验流程，可用于复现实验历史或做对照，不是当前 Random500 论文主实验的首选入口。尤其是 Exp2 完整网格搜索规模很大，服务器主实验不要从这里启动。

回归冒烟测试：

```bash
cd ./beforereview
PYTHONPATH=xgboost-master/python-package \
  python3 exp12/scripts/exp1_ordinal.py --mode quick \
  --datasets airfoil_self_noise.csv \
  --models current_metagb xgb_cpu \
  --outer-folds 2 --inner-folds 2 --max-candidates 1 \
  --task-workers 1 --n-jobs 1
```

旧完整批量运行：

```bash
cd ./beforereview
PYTHONPATH=xgboost-master/python-package \
  python3 exp12/run_all_full.py start --task-workers 16 --n-jobs 1

python3 exp12/run_all_full.py status
```

当前 `run_all_full.py` 会顺序跑完整五个脚本：`exp1_ordinal`、`exp1_drop`、`exp2_ordinal`、`exp2_onehot`、`exp2_drop`。Exp2 是完整网格搜索，默认规模很大；如果只是验证旧流程环境，使用下面的前台小规模命令：

```bash
cd ./beforereview
PYTHONPATH=xgboost-master/python-package \
  python3 exp12/run_all_full.py start --wait \
  --task-workers 1 --n-jobs 1 \
  --outer-folds 2 --inner-folds 2 \
  --max-candidates 1 --limit-grid-candidates \
  --continue-on-failure
```

Linux wrapper 等价：

```bash
cd ./beforereview
PYTHONPATH=xgboost-master/python-package bash exp12/run_all_full_linux.sh start --task-workers 16 --n-jobs 1
PYTHONPATH=xgboost-master/python-package bash exp12/run_all_full_linux.sh status
```

旧流程结果和日志默认写到：
