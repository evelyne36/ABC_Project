# XGBoost 与 MetaGB 超参数搜索空间

## 目标

Random300 和 Random600 使用同一套可复现的共享 backbone 候选，用于公平比较
`xgb_cpu` 与 `current_metagb`。

固定随机种子时：

```text
Random300 candidates == Random600 candidates[:300]
```

XGBoost 与 MetaGB 的第 `i` 个候选共享相同 backbone 参数。旧版
`configs_xgboost.json` 不再参与候选生成；`--xgb-config` 仅为命令兼容保留，并会记录
为已忽略。

## 公共搜索参数

| 统一参数 | 分布 | XGBoost 映射 | MetaGB 映射 |
|---|---|---|---|
| `learning_rate` | `LogUniform([0.005, 0.1])` | `learning_rate` | `learning_rate` |
| `max_depth` | `LogUniformInt([4, 10])` | `max_depth` | `max_depth` |
| `subsample` | `Uniform([0.6, 1.0])` | `subsample` | `subsample` |
| `colsample_bytree` | `Uniform([0.6, 1.0])` | 按树采样 split features | 按树采样 condition features |
| `n_estimators` | `Choice([200, 400, 600, 800])` | `n_estimators` | `n_estimators` |
| `max_bin` | `Choice([255])` | `max_bin` | `max_bin` |
| `lambda_l2` | `LogUniform([1e-4, 5.0])` | `reg_lambda` | `metagb_lambda_l2` |

`lambda_l2` 是候选生成阶段使用的统一概念名称。训练时不会直接传入模型，而是映射为
各模型对应的 L2 参数。

## XGBoost 参数

### 搜索参数

XGBoost 仅搜索上述公共参数。

### 固定参数

| 参数 | 固定值 | 原因 |
|---|---:|---|
| `min_child_weight` | `1.0` | 使用宽松默认约束，不与 MetaGB 行数约束强行等价 |
| `reg_alpha` | `0.0` | MetaGB 没有对应 L1 正则项 |
| `grow_policy` | `"depthwise"` | 与当前 MetaGB updater 的深度生长方式对齐 |
| `colsample_bylevel` | `1.0` | 只使用按树特征采样 |
| `colsample_bynode` | `1.0` | 只使用按树特征采样 |

`max_cat_to_onehot` 和 `max_leaves` 不显式设置。类别特征在进入模型前已按实验选项完成
drop、one-hot 或 ordinal 预处理。

## MetaGB 参数

### 搜索参数

| 参数 | 取值 | 作用 |
|---|---|---|
| `pred_feature_fraction` | `0.1, 0.2, ..., 1.0` | 独立采样 predictive features；bias feature 始终保留 |
| `metagb_score_agg` | `0, 1, 2` | 控制同一 condition split 下 predictive-feature 得分的聚合方式 |

两个参数组成 `10 × 3 = 30` 个联合组合，并按候选索引循环分配：

```text
(0.1, 0), (0.1, 1), (0.1, 2),
(0.2, 0), (0.2, 1), (0.2, 2),
...
(1.0, 0), (1.0, 1), (1.0, 2)
```

因此：

```text
Random300: 每个联合组合 10 个；每个 pred 值 30 个；每个 score_agg 值 100 个
Random600: 每个联合组合 20 个；每个 pred 值 60 个；每个 score_agg 值 200 个
```

### `score_agg` 选项

| 值 | 含义 |
|---:|---|
| `0` | 在 condition/predictive/bin 候选中使用全局最佳得分，最接近直接最大化 split gain |
| `1` | 对 predictive-feature 维度的得分采用平均聚合，偏向整体稳定表现 |
| `2` | 对 predictive-feature 维度的得分采用中位数聚合，降低极端 predictive feature 的影响 |

`score_agg=3` 暂不进入主搜索，因为当前实现涉及全局 C `rand()`，并行和复现语义不够稳健。

### 固定参数

| 参数 | 固定值 | 说明 |
|---|---:|---|
| `metagb_min_data_in_leaf` | `1` | 使用宽松固定行数约束 |
| `metagb_cond_pred_share` | `false` | condition 与 predictive features 独立采样，但允许重叠 |
| `metagb_leaf_only_use_bias` | `false` | 主 MetaGB 允许选择真实 predictive feature |

### `min_data_in_leaf` 的回归与分类解释

`metagb_min_data_in_leaf` 限制叶子样本行数，而 XGBoost 的 `min_child_weight` 限制叶子
Hessian 总和。

- 回归平方误差通常有 `hessian=1`，两种约束较接近。
- 分类任务的 Hessian 随预测概率变化，两种约束不语义等价。

主实验将二者都固定为宽松值 `1`，目的是避免任一模型获得额外调参自由度，而不是宣称
两者约束完全等价。更大的 `metagb_min_data_in_leaf` 应作为 MetaGB 专项消融单独研究。

## Pred0 配对消融

`current_metagb_pred0` 与对应 XGBoost 候选共享全部公共 backbone 参数，并设置：

```text
pred_feature_fraction = 0.0
metagb_lambda_l2 = paired XGBoost reg_lambda
metagb_score_agg = 0
```

该组用于检查 bias-only MetaGB 退化路径，不进入主 MetaGB 搜索。

## 随机种子合同

共享 backbone 使用只依赖 `seed` 和候选索引的确定性随机流。候选预算只负责截断该流，
不会改变已有候选：

```text
same seed + same index -> same shared backbone
Random300 candidates == Random600 candidates[:300]
different seed -> different shared backbones
```

该合同由 `tests/test_random_search_contract.py` 验证。
