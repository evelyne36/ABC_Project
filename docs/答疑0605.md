# current_metagb 工程与论文答疑（0605）

> 更新时间：2026-06-10  
> 结论口径：区分“代码直接证据”“基于证据的推断”“当前尚未证明”。  
> 本文中的“分类正确”主要指论文主路径：`binary:logistic` 与 multiclass
> `one_output_per_tree` scalar 路径，而不是宣称所有实验性分支和所有 XGBoost
> 能力均已得到完整验证。

## 一、总体结论

1. **current_metagb 不是直接调用原版 `metagb.c`，而是将原版 MetaGB v3
   `train_simple` 的核心语义重新实现为 XGBoost CPU histogram tree updater。**
   它保留 conditional feature / predictive feature 分离、bias predictive
   feature、叶输出 `beta * x_j`、原版采样顺序和原版分箱代表值等核心设计；
   同时复用 XGBoost 的 objective、boosting loop、DMatrix、GradientPair、RegTree、
   prediction、serialization 与 sklearn 接口。

2. **论文主路径的分类扩展在数学机理上成立，而且与 XGBoost 的二阶 boosting
   框架一致。** XGBoost objective 先根据分类 loss 产生梯度和 Hessian；
   current_metagb updater 再在受限叶函数 `f(x)=beta*x_j` 上求二阶近似最优系数。
   因此，它不是把回归预测结果事后强行转成类别，而是真正使用 logistic /
   softmax loss 的梯度训练 MetaGB 树。

3. **目前不能严谨地声称“整个工程已经全面正确并达到顶会投稿标准”。**
   更准确的表述是：scalar 主路径已经具有清晰的数学依据、端到端实现闭环和基础
   smoke/round-trip 验证；但完整 Random600 主结果、统计显著性、更多强基线、
   边界能力测试、并发随机性、实验性 vector 分支验证等仍存在明显缺口。

4. **嵌入版相对原版 standalone MetaGB 的效率提升是有依据的，但不应声称其普遍
   快于普通 XGBoost。** 普通 XGBoost 只构建常规 gradient/hessian histogram；
   MetaGB 需要统计 conditional-feature × predictive-feature × bin，计算负担天然更重。

## 二、current_metagb 与 XGBoost 的实验流程和设计

### 2.1 主实验流程

Random600 主入口默认比较 `xgb_cpu` 与 `current_metagb`，覆盖 regression、
binary、multiclass；每模型 600 个候选，outer 5-fold、inner 4-fold nested CV：

- `random600/scripts/run_random600_full.py:23-31`
- `random600/utils/runner.py:346-359`
- `random600/utils/runner.py:394-398`
- `random600/utils/runner.py:490-515`

每个 outer fold 内：

1. outer train/test 划分；
2. 在 outer train 上进行 inner CV；
3. 依据 inner primary metric 选择超参数；
4. 使用整个 outer train 重训；
5. 只在 outer test 上报告最终结果。

任务主指标为：

- regression：RMSE，越低越好；
- binary：AUC，越高越好；
- multiclass：logloss，越低越好。

证据：`random600/utils/metrics.py:16-20`。

### 2.2 公平性应如何表述

**已做到：**

- 两种模型使用相同 candidate budget；
- 共享搜索 `learning_rate`、`max_depth`、`subsample`、`colsample_bytree`、
  `n_estimators`、`max_bin` 和统一映射的 `lambda_l2`；
- 相同 outer/inner splits、相同数据预处理与任务指标；
- 主实验默认 `task-workers=16, n_jobs=1`，避免模型内部线程数不同造成不公平。

**需要谨慎：**

- 当前 `load_dataset()` 在 outer split 之前对全数据执行 drop/one-hot/ordinal
  factorization：`random600/utils/runner.py:201-250`，之后才执行 split：
  `random600/utils/runner.py:394-398`。这不直接使用测试标签选择模型，但测试折参与
  类别词表构造和样本过滤，不符合最严格的 fold-local preprocessing 标准。
- XGBoost 与 current_metagb 的主候选逐个共享 backbone；统一 `lambda_l2` 分别映射为
  `reg_lambda` 与 `metagb_lambda_l2`。
- `current_metagb` 额外均衡覆盖 `pred_feature_fraction=0.1..1.0`；
  `current_metagb_pred0` 使用相同 backbone 并设置 `pred_feature_fraction=0`。
- `min_child_weight=1` 与 `metagb_min_data_in_leaf=1` 均固定为宽松约束，但分类任务中
  Hessian 总和与样本行数不语义等价。

论文中建议表述为：

> We use equal search budgets and paired shared-backbone candidates for the main comparison.
> MetaGB additionally searches balanced predictive-feature fractions, while the pred0 ablation
> uses the same backbone with bias-only predictive leaves.

## 三、current_metagb 如何从原版回归扩展到分类

### 3.1 原版 MetaGB 为什么只支持回归

原版 v3 `train_simple` 内部直接固定：

```text
gradient_i = yhat_i - y_i
hessian_i = 1
```

证据：`metagb/metagb.c:3348-3364`。

因此原版不是一个接收任意 objective 梯度的通用 updater，而是自行实现平方误差回归
boosting。Python 通过 CFFI 调用 `lib.train_simple`，证据：
`metagb/metagb_utils.py:248-285`。

### 3.2 嵌入版分类的真正机制

嵌入版不再自己定义 loss，而是消费 XGBoost objective 生成的 `GradientPair`。

对于任意当前 margin `F_i`，将一个叶子的输出限制为：

```text
f_i = beta * x_ij
```

对 loss 做二阶近似并加入 L2：

```text
Q(beta)
  = sum_i [g_i * beta*x_ij + 1/2 * h_i * (beta*x_ij)^2]
    + 1/2 * lambda * beta^2
```

令导数为零：

```text
beta*
  = - sum_i(g_i*x_ij)
    / [sum_i(h_i*x_ij^2) + lambda]
```

对应实现：

- 累积 `grad_x=sum(g*x)`、`hess_xx=sum(h*x^2)`：
  `beforereview/xgboost-master/src/tree/updater_metagb_hist.cc:49-58`
- score 与 weight：
  `beforereview/xgboost-master/src/tree/updater_metagb_hist.cc:126-132`
- 叶值写入：
  `beforereview/xgboost-master/src/tree/updater_metagb_hist.cc:538-566`
- 预测输出 `leaf_weight * predictive_feature_value`：
  `beforereview/xgboost-master/src/predictor/cpu_predictor.cc:75-104`

因此分类扩展的本质是：

> loss 仍由 XGBoost classification objective 定义；MetaGB 改变的是每棵树可拟合的
> 基函数形式，从分区内常数更新变为分区内单特征线性更新。

### 3.3 二分类是否正确

对于 `binary:logistic`，XGBoost 使用：

```text
p_i = sigmoid(F_i)
g_i = p_i - y_i
h_i = p_i * (1-p_i)
```

证据：

- `beforereview/xgboost-master/src/objective/regression_loss.h:64-73`
- `beforereview/xgboost-master/src/objective/regression_obj.cu:183-195`

MetaGB 使用这些 `g_i,h_i` 求 `beta*x_j` 的最优二阶更新，树输出加到 raw margin，
最终由 objective 的 `PredTransform` 应用 sigmoid：
`beforereview/xgboost-master/src/objective/regression_obj.cu:201-208`。

**结论：`binary:logistic` 主路径机理正确，且是真正按 logistic loss 训练。**

### 3.4 多分类是否正确

XGBoost `multi:softprob` 根据所有类别 margin 计算 softmax 概率，并产生
`[n_samples, K]` 的 gradient/hessian：

- `beforereview/xgboost-master/src/objective/multiclass_obj.cu:77-139`
- softmax probability transform：
  `beforereview/xgboost-master/src/objective/multiclass_obj.cu:143-163`

默认 `one_output_per_tree` 路径逐类别抽取一个 gradient column，每轮构建 K 棵 scalar
MetaGB 树：

- `beforereview/xgboost-master/src/gbm/gbtree.cc:285-308`
- updater 明确要求 scalar tree 每次只有一个 gradient column：
  `beforereview/xgboost-master/src/tree/updater_metagb_hist.cc:1569-1572`

**结论：scalar multiclass 路径机理正确，并与 XGBoost 的标准 class-wise scalar-tree
训练路径一致。** 但需说明：XGBoost multiclass 使用的是对角 Hessian 上界近似，而非
完整 softmax Hessian；这是 XGBoost 本身的标准近似，不是 current_metagb 新引入的错误。

### 3.5 分类正确性的实测证据

2026-06-10 在当前工作区执行：

```text
python3 -m pytest -q beforereview/xgboost-master/tests/python/test_metagb.py
结果：14 passed
```

测试覆盖 regression、`binary:logistic`、`binary:logitraw`、`multi:softprob`、
`multi:softmax`、概率和为 1、模型保存加载 round-trip。测试定义见：
`beforereview/xgboost-master/tests/python/test_metagb.py:70-182`。

额外数值探针结果：

```text
binary predict_proba 与 sigmoid(output_margin) 最大误差：0
binary base/train logloss：0.68939 -> 0.33507

multiclass predict_proba 与 softmax(output_margin) 最大误差：1.19e-7
multiclass base/train logloss：1.08587 -> 0.52430
```

另用 80 特征数据比较 `row_serial` 与 `cf_parallel`，regression、binary logistic、
multiclass softprob 三类任务的 output margin 最大差异均为 `0.0`。

### 3.6 仍不能过度声称的分类能力

1. `binary:logitraw` 的 objective 按定义输出 raw margin，而不是 probability。
   当前 smoke test 只检查 `predict_proba` 有限且两列和为 1，没有检查每项位于
   `[0,1]`。额外探针发现其所谓 `predict_proba` 可出现 `-10.50` 和 `11.50`。
   因此论文主实验应坚持 `binary:logistic`；不能把 `binary:logitraw` 的
   `predict_proba` 当作合法概率或用于标准 logloss。

2. experimental `multi_output_tree` vector 分支虽然已有实现，但缺少 MetaGB 专属分类
   测试；论文主结论应使用 scalar path，vector 只作为实验性消融。

3. 当前测试主要是 smoke 和 round-trip，不是数学 oracle、有限差分 gradient 检验或
   全能力兼容性证明。

4. 含缺失值时存在明确的路由闭环风险：训练分箱和 updater 内部分区将缺失/不存在值
   当作数值 0，但正式 CPU predictor 遇到缺失时使用树的 `DefaultChild`；MetaGB
   split 当前固定 `default_left=false`。当 `0 <= split_cond` 时，训练阶段可能将
   缺失样本放入左子树，而正式预测送入右子树。主结论应限制为已清洗的 dense numeric
   数据，或在投稿前补齐缺失值一致性。

5. 叶系数是在分箱代表值 `x_bin` 上拟合，但推理时乘原始值 `x_raw`。这是为保留原版
   MetaGB 语义而采用的近似，不是对最终 raw-value predictor 的严格同一目标优化。

## 四、原版 MetaGB 如何迁移进 XGBoost

### 4.1 保留的算法语义

- conditional feature 决定树分区；
- predictive feature 决定叶响应；
- bias feature 恒为 1，使叶可以选择常数响应；
- 叶响应为 `beta*x_j`；
- 保留原版行采样、conditional feature 采样、predictive feature 采样顺序；
- 保留原版 `srand(1)` / C `rand()` 采样习惯；
- 训练统计使用 MetaGB 分箱代表值，预测使用 raw feature value；
- 保留 `score_agg=0..3` 和原版默认极低的 `min_gain_to_split`。

相关证据：

- bias predictive feature：`updater_metagb_hist.cc:218-227`
- 原版随机种子：`metagb/metagb.c:3357`
- 嵌入版随机种子：`updater_metagb_hist.cc:319-323`
- 训练代表值：`updater_metagb_hist.cc:381-390`
- raw prediction：`cpu_predictor.cc:91-100`

### 4.2 替换的工程结构

原版用递归 DFS 构造私有数组树：
`metagb/metagb.c:3212-3245`。

嵌入版使用 `RegTree::ExpandNode`，并按当前层 `expand_set` 扩展：

- `updater_metagb_hist.cc:1276-1320`
- `updater_metagb_hist.cc:1605-1635`

叶 predictive feature 作为树模型元数据存储，并进入 JSON serialization：

- `beforereview/xgboost-master/include/xgboost/tree_model.h:586-587`
- `beforereview/xgboost-master/src/tree/tree_model.cc:1207-1251`
- `beforereview/xgboost-master/src/tree/tree_model.cc:1299-1315`

### 4.3 未迁移或仅部分支持的内容

- 原版旧版本中的 prior conditional features、`depth_sep`、层级 feature selection；
- 原版部分额外 score aggregation 编号；
- 原版 `normalize`、`use_delta`、`leaf_use_all_pred_feature` 等旋钮；
- GPU、external-memory、多 row page；
- 通用 XGBoost grow-policy 切换；
- vector multiclass 仍是 experimental。

## 五、嵌入版做了哪些优化，为什么更快

### 5.1 原版主要成本

原版每个节点为完整
`n_cond * n_pred * max_bin` 直方图执行 `malloc + memset + free`：

- `metagb/metagb.c:2923-2928`
- `metagb/metagb.c:3124-3125`

### 5.2 嵌入版保留的主要优化

- DMatrix 不变时缓存原始分箱：`updater_metagb_hist.cc:414-423`
- 每棵树缓存 predictive train values：`updater_metagb_hist.cc:393-411`
- predictive value 采用 row-major 连续布局；
- 复用 histogram / split / leaf workspaces；
- 预取当前节点 gradient/hessian：`updater_metagb_hist.cc:712-720`
- 自动选择 `row_serial` 或 `cf_parallel`：
  `updater_metagb_hist.cc:291-307`
- conditional-feature slice 并行构建三维直方图：
  `updater_metagb_hist.cc:796-817`
- 并行 split evaluation：`updater_metagb_hist.cc:838-973`
- 复用 XGBoost prediction cache、booster loop、模型和接口基础设施。

代表性宽表 QSAR 配置中，文档记录：

```text
auto / no subtraction：约 2.01s
row_serial / no subtraction：约 10.96s
```

证据：`METAGB_HIST_BUILD_OPTIMIZATION_PLAN.md:161-172`。

该结果只能表述为“代表性宽表路径上的实测提升”，不能外推为所有数据集的普遍倍数。
小表中并行调度开销可能抵消收益。

### 5.3 为什么 histogram subtraction 默认关闭

当前 subtraction 实现需要缓存/复制完整三维直方图，成本大；代表性测试中
`hist_subtract=true` 反而更慢。因此默认 `false`：
`METAGB_HIST_BUILD_OPTIMIZATION_PLAN.md:182-204`。

## 六、“宽表上按 conditional-feature slice 并行，无需原子操作”是什么意思

### 6.1 三维直方图布局

一个节点的 MetaGB histogram 逻辑上为：

```text
hist[conditional_feature][predictive_feature][bin]
```

设：

```text
hist_size   = n_pred * n_bins
hist3d_size = n_cf * hist_size
```

证据：`updater_metagb_hist.cc:722-728`。

对第 `cf_idx` 个 conditional feature，其独占连续内存范围是：

```text
[cf_idx * hist_size, (cf_idx + 1) * hist_size)
```

代码通过：

```cpp
auto* cf_slice = node_hist.data() + cf_idx * hist_size;
```

获得该 slice，然后只写：

```cpp
cf_slice[pi * n_bins + bin]
```

证据：`updater_metagb_hist.cc:799-815`。

### 6.2 小案例

假设：

```text
n_cf = 4
n_pred = 2
n_bins = 4
hist_size = 8
hist3d_size = 32
```

则四个 conditional feature 的写集合为：

| conditional feature | 独占地址范围 |
|---|---|
| `cf0` | `[0, 8)` |
| `cf1` | `[8, 16)` |
| `cf2` | `[16, 24)` |
| `cf3` | `[24, 32)` |

假设线程 A 负责 `cf0`，线程 B 负责 `cf1`。即使同一条样本在两个 conditional
feature 上都落入 bin 2，它们最终写入的也是不同 slice：

```text
线程 A：0  + pi*4 + 2
线程 B：8  + pi*4 + 2
```

地址不重叠，因此：

- 不会发生两个线程同时修改同一个 `MetaGBStats`；
- 不需要锁；
- 不需要 `atomic add`；
- 不需要每线程复制一份完整三维 histogram 再归并。

同一个 `cf` slice 内，多条样本可能落入相同 `(pi,bin)`，但它们由负责该 `cf_idx`
的同一个线程按顺序累加，所以仍没有数据竞争。

### 6.3 为什么宽表能提速

宽表通常具有较大的 `n_cf` 和 `n_pred`：

1. `n_cf` 大，能够给多个线程分配足够多的独立 slice；
2. 每个 slice 内有足够计算量，能摊薄 OpenMP 调度成本；
3. 每个线程写连续 slice，predictive value 也按 row-major 连续读取；
4. 没有原子操作的串行化开销；
5. 没有 row-parallel 所需的“每线程完整 histogram + 最终 reduction”成本。

自动策略只在 `threads>1`、`n_cf>=4` 且
`n_cond*n_cf*n_pred>=50000` 时选择 `cf_parallel`：
`updater_metagb_hist.cc:291-306`。

**限制：** `cf_parallel` 对每个 conditional feature 都重新扫描节点行；小表或
`n_cf` 很少时，扫描和线程调度开销可能超过收益。并行度上限也受 `n_cf` 限制。

## 七、与 CatBoost depth-wise、level-wise 的区别及 MetaGB 树优势

### 7.1 current_metagb 是否支持 level-wise

嵌入版维护当前层的 `expand_set`，先应用这一层全部候选，再生成下一层候选：
`updater_metagb_hist.cc:1612-1635`。

因此 current_metagb 当前实际是固定的 **level-wise / depth-wise expansion**。
每个节点独立选择自己的最佳 split，不要求同一层所有节点使用同一 split。

### 7.2 与 CatBoost 的关系

- CatBoost `SymmetricTree`：同一层所有节点使用同一个 split；
- CatBoost `Depthwise`：按层生长，但每个非终止叶独立选择最佳 split；
- CatBoost `Lossguide`：每次优先扩展全局最佳叶，属于 leaf-wise。

current_metagb 更接近 CatBoost `Depthwise`，而不是 CatBoost 默认
`SymmetricTree`。它没有使用 XGBoost 通用 grow-policy driver，因此设置
`grow_policy=lossguide` 不能将 current_metagb 切换为 leaf-wise。

当前工程没有 CatBoost 实验结果，因此不能声称实证优于 CatBoost。

### 7.3 MetaGB 树的主要优势

1. **分区变量和预测变量解耦。** 一个特征可以负责“在哪里生效”，另一个特征负责
   “如何影响输出”。
2. **叶是稀疏的一维局部线性模型。** 比常数叶表达力强，又比完整多变量线性叶更轻。
3. **可用较浅结构表达区域依赖线性关系。**
4. **bias predictive feature 使函数类包含常数叶。**

论文中宜表述为“函数类层面包含普通常数叶”，不宜声称实现结果或每次训练均与普通
XGBoost bitwise 等价，因为两者的分箱、采样、正则化和 split gain 实现不同。

主要代价：

- 训练复杂度和内存为 conditional × predictive × bin；
- 对 predictive feature 数值尺度更敏感；
- 多了一层 predictive feature selection，可能增加过拟合风险；
- 普通 XGBoost 通常仍明显更快。

## 八、当前工程是否“整体正确”

### 8.1 可以肯定的部分

**高置信度：**

- scalar regression、binary logistic、scalar multiclass 的 objective → gradient/hessian
  → MetaGB leaf/split → margin → probability 闭环逻辑一致；
- 叶系数公式是受限基函数 `beta*x_j` 下二阶近似目标的解析最优解；
- prediction、prediction cache 和 serialization 已接入；
- 当前专属测试全部通过；
- `row_serial` 与 `cf_parallel` 在本次三任务探针中得到完全相同 margin；
- nested CV 的 outer-test 隔离流程正确。

### 8.2 重要风险和未证明项

**P1：论文提交前应处理或明确限制**

1. **当前仓库只看到 smoke Random600 结果，没有完整主实验结果。**
   因此尚不能支撑最终性能结论。
2. **尚未实现计划中的统计显著性输出。**
   `论文写作.md:153-160` 规划了 paired bootstrap / Wilcoxon / critical difference，
   但当前代码搜索未发现对应实现。
3. **`metagb_pred_value_type` 是脚本暴露的参数，但 C++ `TrainParam` 中没有对应字段。**
   它目前会作为 unknown parameter 被传递/忽略，不能在论文中描述为已生效机制。
4. **随机采样使用进程全局 C `rand()` / `srand(1)`，不真正服从 XGBoost
   `random_state`。** 多进程 task-worker 场景相互隔离，但同一进程并发训练和可复现性
   仍有风险。
5. **`score_agg=3` 在 OpenMP 并行 split evaluation 内调用全局 `rand()`：**
   `updater_metagb_hist.cc:923-937`。这可能导致数据竞争或非确定行为。主实验固定
   主搜索现纳入 `score_agg=0,1,2`，但明确排除 `score_agg=3`；不能宣称 0..3
   均已严谨并行验证。
6. **缺失值当前被当作数值 0，而不是完整遵循 XGBoost default direction。**
   并且训练路由与正式 predictor 的 missing default route 可能不一致。证据：
   `updater_metagb_hist.cc:182-197`、`430-436`、`1306-1319`，
   `cpu_predictor.cc:81-89`。若论文数据已预处理为无缺失值，应明确报告；否则需修复
   并单独验证。
7. **预处理没有严格折内化。** one-hot/ordinal 编码与缺失行过滤在 outer split 前对
   全数据完成：`random600/utils/runner.py:201-250`。这可能带来类别词表信息进入测试
   折等方法学争议。
8. **`total_train_time_sec` 不是完整 Random600 搜索成本。** 它主要记录获胜候选的
   inner time 加最终重训时间；比较完整搜索吞吐应使用 `task_elapsed_sec`，并单独报告
   每候选/每 fit latency，避免效率表述误导。

**P2：覆盖与工程完备性缺口**

- 缺少 vector MetaGB 分类专属测试；
- 缺少 sample weight、class imbalance、missing value、稀疏矩阵、categorical、
  monotonic constraints、interaction constraints 等兼容性测试；
- updater 明确只支持 CPU hist/auto、单 tree per updater call、单 in-memory row page：
  `updater_metagb_hist.cc:1475-1506`；
- GPU predictor 没有实现 MetaGB 的 `leaf_weight * predictive_feature` 语义；训练虽
  限制为 CPU，但加载模型后改变 device 等边界路径仍需防护或测试；
- 当前专属分类测试主要检查 shape、finite、概率和、round-trip，没有直接检查
  objective 数值、梯度有限差分或基准 oracle；
- 并行动态调度下完全确定性的 tie-breaking 尚未被系统证明；
- 代表性性能数据和优化文档充分，但尚不是跨机器、多次重复、带置信区间的系统基准。

### 8.3 最终判断

**“算法主路径是否合理、分类机理是否正确？”：是，高置信度。**

**“实现是否已被证明在支持范围内完全无误？”：否；已有较强正面证据，但测试覆盖
仍不足以做全面正确性声明。**

**“工程目前是否已经符合客观严谨的顶会最终投稿标准？”：尚未。**

它已经具备顶会论文工程原型和主实验框架，但投稿前至少需要：

- 完成全量主实验而非 smoke；
- 增加统计显著性与 effect-size 分析；
- 增加 strong baselines，并明确 CatBoost/LightGBM/普通 XGBoost 的搜索预算；
- 将 preprocessing 改为严格 fold-local pipeline，或明确证明当前预处理不影响结论；
- 对 scalar 主路径增加 oracle/数值正确性测试和边界测试；
- 将 vector、`score_agg=3`、missing 等未成熟能力明确降级为限制或 appendix；
- 报告多次计时、硬件、线程设置、版本、失败任务和完整复现材料。

## 九、论文中建议使用的规范表述

### 分类机理

> current_metagb reuses XGBoost classification objectives to compute first- and
> second-order derivatives with respect to raw margins. The embedded updater then
> optimizes a restricted leaf response of the form `beta*x_j`, replacing the
> conventional constant leaf update while preserving the second-order functional
> gradient boosting framework.

### 正确性边界

> Our main implementation uses binary logistic classification and the scalar
> one-output-per-tree multiclass strategy. The vector-leaf branch is treated as
> experimental and is excluded from the primary correctness and accuracy claims.

### 效率

> For wide tables, histogram construction is parallelized over disjoint
> conditional-feature slices. Each worker exclusively updates one slice of the
> conditional-by-predictive-by-bin histogram, eliminating atomic updates and
> thread-local histogram reduction. This optimization improves embedded MetaGB
> throughput on wide-feature workloads, but does not imply that MetaGB is generally
> faster than standard constant-leaf XGBoost.

## 十、当前工程优化与问题总结

### 10.1 相较原版 MetaGB 的工程优化

#### 1. 从回归原型扩展为多任务训练框架

原版 MetaGB v3 在 `train_simple` 内固定使用平方误差梯度：

```text
g_i = yhat_i - y_i
h_i = 1
```

当前嵌入版复用 XGBoost objective，根据任务产生 `GradientPair`，支持：

- 平方误差回归；
- `binary:logistic` 二分类；
- `multi:softprob` scalar multiclass；
- 实验性 multiclass vector-leaf 路径。

这使 MetaGB 从专用回归算法原型扩展为可复用的 XGBoost 多任务 tree updater。

#### 2. 完整复用 XGBoost 工程基础设施

原版通过 Python CFFI 调用私有 C 实现，并使用自定义数组存储树。

当前工程将 MetaGB 实现为 XGBoost CPU hist updater，复用：

- DMatrix 和数据加载；
- objective 与 GradientPair；
- boosting loop；
- RegTree 模型结构；
- prediction cache；
- CPU predictor；
- 模型 JSON 保存与加载；
- sklearn `XGBRegressor` / `XGBClassifier` 接口。

因此训练、预测、模型持久化和实验调用均更加统一。

#### 3. 缓存和内存访问优化

当前嵌入版减少了大量重复计算和内存操作：

- DMatrix 不变时缓存原始 MetaGB 分箱；
- 每棵树缓存 sampled predictive features 的训练值；
- predictive value 使用 row-major 连续布局；
- 预取当前节点 gradient 和 Hessian；
- 复用 leaf、histogram 和 split workspace；
- 避免原版每个节点重复执行完整 histogram 的
  `malloc + memset + free`。

这些优化主要降低了重复分箱、内存分配、函数调用和随机访存成本。

#### 4. Conditional-feature slice 并行

MetaGB 三维直方图布局为：

```text
hist[conditional_feature][predictive_feature][bin]
```

当前工程可让不同线程分别处理不同 conditional-feature slice。每个线程独占自己的
写入区域，因此：

- 不需要原子操作；
- 不需要锁；
- 不需要每线程复制完整三维 histogram；
- 不需要最终 histogram reduction。

该优化对宽表尤其有效。代表性 QSAR 宽表配置中：

```text
cf_parallel / auto：约 2.01 至 2.06 秒
row_serial：约 10.96 秒
```

该结果只代表特定宽表路径；小表上并行调度开销可能抵消收益。

#### 5. 自动 histogram 构建策略

`auto` 模式根据线程数、conditional feature 数量和估计工作量，自动选择：

- 小任务使用 `row_serial`；
- 宽表或高工作量节点使用 `cf_parallel`。

当前选择 `cf_parallel` 的主要条件为：

```text
threads > 1
n_cf >= 4
n_cond * n_cf * n_pred >= 50000
```

这避免了在小数据集或特征较少的节点上盲目启用并行。

#### 6. 分裂评估并行化

直方图构建完成后，当前工程还会并行评估不同 conditional feature 的最佳 split。

原版 MetaGB 基本采用串行递归构树；嵌入版能够利用 OpenMP 并行处理较宽的特征空间。

#### 7. 保留并扩展 MetaGB 核心表达能力

当前工程保留了：

- conditional feature 与 predictive feature 解耦；
- 叶响应 `beta*x_j`；
- bias predictive feature；
- 独立 predictive feature sampling；
- 原版分箱代表值、采样顺序和主要 score aggregation 语义。

同时新增实验性 multiclass vector-leaf 路径，可共享树结构，并允许不同类别选择不同
predictive features。

#### 8. 建立较完整的实验工程

相较原版 MetaGB 的简单实验脚本，当前工程新增：

- Random300 / Random600 搜索；
- outer/inner nested CV；
- regression、binary、multiclass 数据集流程；
- 候选配置保存；
- 参数审计；
- 每任务日志和失败记录；
- 训练与预测计时；
- predictive fraction 分析；
- `current_metagb_pred0` 机制消融。

### 10.2 当前工程的主要问题

#### 1. 全量实验尚未完成

当前仓库主要存在 smoke 实验结果，例如：

```text
2 outer folds
2 inner folds
10 candidates
```

计划中的正式 Random600 应覆盖：

```text
5 outer folds
4 inner folds
600 candidates
全部目标数据集
```

因此当前尚不能充分佐证：

- MetaGB 是否在多数数据集上优于 XGBoost；
- 优势是否具有统计显著性；
- 哪类数据集最适合 MetaGB；
- 性能收益是否足以抵消训练成本；
- binary 和 multiclass 扩展是否具有稳定经验优势。

这是当前论文结论最核心的证据缺口。

#### 2. 缺少统计显著性分析

当前聚合结果主要提供 mean/std，尚未实现论文规划中的：

- Wilcoxon paired test；
- Friedman test；
- Holm 多重比较校正；
- effect size；
- critical difference diagram；
- bootstrap confidence interval。

因此不能仅依据少量数据集上的平均结果声称“显著优于 XGBoost”。

#### 3. 缺少足够的强基线

当前主实验主要比较：

```text
xgb_cpu vs current_metagb
```

正式论文仍应考虑：

- CatBoost；
- LightGBM；
- XGBoost 不同 grow policy；
- 其他 model-tree 或 linear-leaf 方法；
- 原版 standalone MetaGB；
- `current_metagb_pred0`；
- 固定 backbone 下的 predictive fraction 消融。

否则审稿人可能质疑优势来自搜索空间、超参数预算或实现配置差异。

#### 4. 主搜索不是严格逐参数配对

XGBoost 和 current_metagb 使用相同候选数量及部分共享搜索维度，但候选是独立生成的。

因此严谨表述应为：

> equal candidate budget and shared search dimensions

而不能称为严格相同超参数 backbone 的逐候选公平对比。

`current_metagb_pred0` 使用 XGBoost backbone，更适合作为配对机制消融。

#### 5. 数据预处理没有严格折内化

当前 one-hot、ordinal factorization 和缺失行处理发生在 outer split 之前。

这可能使测试折参与类别词表构造或样本过滤。虽然不一定造成明显目标泄漏，但不符合
最严格的 nested-CV 方法学要求。

#### 6. 缺失值支持存在实现风险

训练时，缺失值或不存在的稀疏值被当作数值 `0`。正式 CPU predictor 遇到缺失值时，
则根据树的 default child 路由。两者可能将同一个缺失样本送入不同子树。

因此当前主结论应限制为：

```text
经过缺失值清理的 dense numeric 数据
```

#### 7. 训练值与预测值存在近似差异

叶系数 `beta` 使用分箱代表值计算，但正式预测时乘原始 feature value：

```text
训练：beta 基于 x_bin 拟合
预测：beta * x_raw
```

这是保留原版 MetaGB 语义的设计，但并不是严格优化最终 raw-value predictor 的同一个
目标。低 `max_bin`、偏态特征或宽数值范围下可能产生更明显影响。

#### 8. 部分参数和实验分支尚不成熟

- `metagb_pred_value_type` 在实验脚本中存在，但 C++ 中未发现实际实现；
- `score_agg=3` 在并行区域使用全局 C `rand()`，可能产生非确定性或数据竞争；
- vector multiclass 路径缺少 MetaGB 专属测试；
- `binary:logitraw` 的 sklearn `predict_proba` 不是合法概率；
- GPU predictor 未实现 MetaGB 叶乘 predictive feature 的语义；
- 当前仅支持 CPU hist、单 in-memory row page。

#### 9. 测试仍偏向 smoke test

现有测试已经验证可训练、预测有限、概率形状和模型保存加载，但仍缺少：

- 人工小数据上的精确 split、gain 和 leaf-weight oracle；
- 有限差分 gradient/Hessian 检验；
- 原版与嵌入版数值一致性测试；
- 缺失值测试；
- sample weight 与类别不平衡测试；
- 不同线程数和随机种子确定性测试；
- 完整实验脚本端到端测试。

#### 10. 效率优势需要谨慎表述

嵌入版的主要效率优势是相较原版 standalone MetaGB，而不是普遍快于普通 XGBoost。

MetaGB 每个节点需要处理：

```text
conditional feature * predictive feature * bin
```

普通 XGBoost 主要处理：

```text
feature * bin
```

因此 MetaGB 训练通常仍明显更慢。论文中的系统贡献应描述为：

> 通过 XGBoost 集成、缓存优化和 conditional-feature slice 并行，使表达能力更强的
> MetaGB 叶模型能够以可接受的成本运行。

而不应描述为：

> MetaGB 普遍比普通 XGBoost 更快。

### 10.3 阶段性总结

当前工程已经完成 MetaGB 从 standalone 回归原型到 XGBoost 兼容、多任务和并行化
研究系统的迁移。核心改进包括分类 objective 集成、模型与接口基础设施复用、缓存
优化、conditional-feature slice 并行，以及完整 nested-CV 实验框架。

然而，目前的证据主要证明了方法可行性和主路径数学正确性，尚不能充分证明其普遍经验
优势。全量 Random600、统计显著性、强基线、严格折内预处理、边界测试和完整复现材料，
仍是正式论文提交前的关键工作。
