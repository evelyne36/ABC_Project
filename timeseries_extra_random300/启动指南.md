# timeseries_extra_random300 启动指南

## 工程目的

`timeseries_extra_random300` 用于补充 time-series 数据，独立于旧 time-series adapter，避免影响既有工程结果。这里的数据和协议尽量贴近顶会 LTSF / multivariate forecasting 常用基准，但模型侧保持为 XGBoost / MetaGB，因此做法是把时间序列转成监督式滑窗 tabular 数据。

核心约束：

- 不打乱时间顺序。
- 外层与内层都使用 expanding-window chronological split。
- 标准化只在训练窗口上 fit，再应用到验证/测试，避免未来信息泄漏。
- 对 date CSV 可加入 month/day/hour/dayofweek 等时间特征。
- time-series 一般无离散特征，不做 onehot；drop/onehot 对该类数据不构成主要变量。

## 与顶会设置的对应关系

当前登记数据来源：

- ETT family：Informer / Autoformer / PatchTST 常见 LTSF 数据，包括 `ETTh1`、`ETTh2`、`ETTm1`、`ETTm2`。
- LSTNet multivariate family：`exchange_rate`，以及后续可扩展的 `electricity`、`traffic`、`solar`。

本工程默认 `seq_len=24`、`pred_len=1`，用于 XGBoost/MetaGB 的成本可控实验。若要更贴近 LTSF 论文长预测设置，可以显式改成 `--seq-len 96 --pred-len 96/192/336/720`，但窗口特征数会随 `seq_len * channels` 增长，MetaGB 成本约随 `samples * features * features` 增长，必须先 smoke。

## 推荐 full 启动

Linux 一键后台启动：

```bash
bash timeseries_extra_random300/run_linux_full.sh
```

默认数据集为 `exchange_rate ETTh1 ETTh2 ILI`。可用环境变量覆盖：

```bash
DATASETS="Weather ILI exchange_rate" SEQ_LEN=24 PRED_LEN=1 TASK_WORKERS=15 N_JOBS=1 bash timeseries_extra_random300/run_linux_full.sh
```

PEMS 与 `traffic/electricity/solar` 已下载并可读取，但维度很宽，不放入默认一键 full；建议先短窗口 smoke 或做通道子集。

注意：`solar_AL` 是原始文件名，不是规范数据集名；规范数据集名是 `solar`。脚本已支持 `solar_AL -> solar` 别名，当前原始文件已落盘在 `timeseries_extra_random300/data/raw/solar_AL.txt`。如果服务器上缺失该文件，可用下面命令重下：

```bash
python3 timeseries_extra_random300/scripts/download_datasets.py --datasets solar_AL --force
```

先跑低压力数据：

```bash
nohup python3 timeseries_extra_random300/scripts/run_timeseries_benchmark.py \
  --mode full \
  --datasets exchange_rate ETTh1 ETTh2 \
  --models xgb_cpu current_metagb \
  --outer-folds 5 \
  --inner-folds 4 \
  --max-candidates 300 \
  --seq-len 24 \
  --pred-len 1 \
  --task-workers 15 \
  --n-jobs 1 \
  --progress-every 50 \
  --run-id timeseries_extra_random300_full_$(date +%Y%m%d_%H%M%S) \
  > timeseries_extra_random300/nohup_logs/timeseries_extra_random300_full.log 2>&1 &
```

说明：当前 time-series runner 已按任务并行执行，任务粒度为 `dataset × outer_fold × model`。`TASK_WORKERS=15` 会最多同时运行 15 个外层任务；`N_JOBS=1` 保持单个 XGBoost 任务内部不再额外开线程，避免 CPU 过度订阅。Linux 服务器优先使用进程池；若运行环境禁止进程池，会自动退到线程池并在 `metadata.json` 记录 `task_executor`。

## 树模型时间序列主实验协议

当前主实验目标是比较同一套时间序列转表格特征下的树模型：

- `current_metagb`
- `xgb_cpu`
- `lgbm_cpu`
- `catboost_cpu`

协议固定为：

- `--split-protocol fixed`
- `--feature-mode window_summary`
- `--target-mode sequence`
- `--output-scope target`
- `--seeds 42` 作为默认第一轮；需要多 seed 时再显式追加，例如 `--seeds 42 43 44`
- `--seq-lens 24 48`
- `--pred-lens 1 6 12`

这里 `pred_len=12` 表示一次预测 `t+1 ... t+12` 的目标变量未来序列，而不是只预测 `t+12` 一个点。这样更贴近主流 multi-horizon forecasting protocol，同时避免 `output_scope=all` 在高维多变量数据上把输出维度膨胀为 `pred_len * channels`。

`window_summary` 的列数上界为：

```text
features <= seq_len * channels + 9 * channels + 6 + 4
         = (seq_len + 9) * channels + 10
```

在预注册最大窗口 `seq_len=48` 下：

- ETT / ILI：`channels=7`，最多 `409` 列。
- `exchange_rate`：`channels=8`，最多 `466` 列。
- `Weather`：`channels=21`，最多 `1207` 列。

PEMS 类宽通道数据若不做通道上限，即使用 `window_summary` 也会达到数万列；因此不建议以未截断形态直接进入主表 full。当前分层脚本默认用 `max_features=64` 保留 PEMS 作为高维多变量补充层；非 PEMS 数据集通道数都低于 64，不受影响。

服务器 full 命令建议：

```bash
nohup python3 timeseries_extra_random300/scripts/run_timeseries_benchmark.py \
  --mode full \
  --split-protocol fixed \
  --datasets exchange_rate ETTh1 ETTh2 Weather ILI ETTm1 ETTm2 \
  --models current_metagb xgb_cpu lgbm_cpu catboost_cpu \
  --feature-mode window_summary \
  --target-mode sequence \
  --output-scope target \
  --seeds 42 \
  --seq-lens 24 48 \
  --pred-lens 1 6 12 \
  --max-candidates 300 \
  --task-workers 15 \
  --n-jobs 1 \
  --progress-every 50 \
  --run-id ts_tree_sequence_window_summary_full_$(date +%Y%m%d_%H%M%S) \
  > timeseries_extra_random300/nohup_logs/ts_tree_sequence_window_summary_full.log 2>&1 &
```

服务器环境需要可导入 `lightgbm` 与 `catboost`；本地若未安装这两个包，仍可先用 `xgb_cpu current_metagb` 做协议 smoke。

## 分层主实验启动

为了先保证有足够的时序数据支撑 `current_metagb` vs 其他树模型的主结论，当前推荐使用分层执行入口：

```bash
bash timeseries_extra_random300/run_linux_tiered_tree.sh
```

默认会按下面顺序逐层运行，每一层都使用同一套公平协议与四个模型：

1. `non_pems`：`ETTh1 ETTh2 ETTm1 ETTm2 exchange_rate ILI Weather`
   - 先跑完全部非 PEMS 数据集，尽快形成完整主表证据。
2. `pems`：`PEMS03 PEMS04 PEMS07 PEMS08`
   - PEMS 系列高维且计算较重，放在非 PEMS 全部组合完成之后。

分层配置文件为：

```text
timeseries_extra_random300/configs/tiered_tree_benchmark.json
```

分层 runner 的调度顺序是 `seed -> tier`：会先跑完一个 seed 下的所有 tier，再进入下一个 seed。默认只跑 `seed=42`；如果设置 `SEEDS="42 43 44"`，则顺序为 `seed42/non_pems -> seed42/pems -> seed43/non_pems ...`。

每个 seed/tier 会写入独立结果目录：

```text
timeseries_extra_random300/results/<base_run_id>__seed<seed>__<tier_name>/
```

父目录会持续合并已经完成的 tier summary：

```text
timeseries_extra_random300/results/<base_run_id>/summary.csv
timeseries_extra_random300/results/<base_run_id>/aggregate.csv
timeseries_extra_random300/results/<base_run_id>/tier_manifest.json
```

只跑非 PEMS 阶段：

```bash
TIERS="non_pems" \
bash timeseries_extra_random300/run_linux_tiered_tree.sh
```

本地或服务器预演命令，不实际训练：

```bash
python3 timeseries_extra_random300/scripts/run_tiered_timeseries_benchmark.py \
  --dry-run \
  --tiers non_pems \
  --base-run-id dryrun_tiered_tree
```

默认参数为：

```text
models=current_metagb xgb_cpu lgbm_cpu catboost_cpu
seeds=42
seq_lens=24 48
pred_lens=1 6 12
feature_mode=window_summary
target_mode=sequence
output_scope=target
max_candidates=300
max_features=64
```

其中 `max_features=64` 只影响 PEMS 这类宽通道数据，用于把 PEMS 的窗口特征控制在可计算范围；ETT、ILI、exchange_rate、Weather 不会被截断。
